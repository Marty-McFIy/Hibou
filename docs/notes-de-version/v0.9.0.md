# Hibou 0.9.0

_21/11/2026_

Première version validée de bout en bout sur une machine réelle : préparation du bundle hors ligne, installation
des trois rôles sur Proxmox, chat et rédaction, agent de code, relecture, priorité, mise à jour, sauvegarde et
restauration. Trente-huit corrections, chacune décrite et prouvée dans le
[journal des corrections](../../JOURNAL-CORRECTIONS.md).

## Nouveautés

- **Profil « ≥ 4 Go »** pour doc et dev : Hibou tourne désormais sur une seule petite carte (validé sur 4 Go,
  processeur sans AVX2). Les profils 24 et 48 Go ont été ramenés sous leur palier de mémoire réel.
- **Export de documents** dans le chat : Word, PDF, PowerPoint, Excel ou Markdown, aux couleurs Hibou,
  téléchargeables depuis la conversation et visibles de leur seul auteur.
- **Compression automatique** des longues conversations : au lieu d’une erreur, les anciens échanges sont résumés.
- **Une instance OpenCode par développeur** : espace de travail, conversations, priorité et commits à son nom.
- **Publication au nom de la personne** : branche `redaction/<personne>/…`, commit et pull request à son nom.
- **Agent de code durci** : `main` protégée dans chaque dépôt qu’il crée, pas de création de dépôt par push,
  commandes toutes faites (`forgejo-nouveau-depot`, `forgejo-pr`), refus d’office des commandes dangereuses
  et de l’affichage des secrets, `.gitignore` de départ.
- **Relecteur** : au plus 10 remarques, sans boucle de répétition ; il signale dans la PR quand il ne peut pas relire.
- **Mises à jour** : Open WebUI suit automatiquement un changement de profil de doc ou de dev ; les outils de
  `hibou-docs` arrivent par pull request ; arrêt si un service redémarre en boucle ; conversations de l’agent conservées.
- **Connexion à Proxmox par Forgejo** opérationnelle (résolution de forge sur l’hôte, émetteur OIDC exact).

## Validé à l’essai

| Domaine | Résultat |
| --- | --- |
| Bundle | 18 Go ; second passage sans retéléchargement en 5 min ; `verifier` en 1 à 2 min |
| Installation | forge 4 min, doc 12 min, dev 15 min (disques durs) ; mise à jour 3 à 4 min |
| doc, profil 4 Go | Qwen3.5 4B, 22 tokens/s ; évaluation rédaction 93 %, vision 100 % |
| dev, profil 4 Go | Qwen3.5 4B, 22 tokens/s ; évaluation code 75 % ; complétion 13 à 16 tokens/s sur le processeur |
| Priorité | une requête prioritaire passe devant les requêtes en attente, sans couper celle en cours |
| Documentation | rédaction, PR, runner, relecture, fusion, site et base du chat mis à jour, réponse sourcée |
| Sauvegarde | 2 min 40 s (14,5 Go compressés) ; restauration complète en 8 min, données intactes |

## À savoir avant de mettre à jour

- Fusionner la pull request « Hibou 0.9.0 : mise à jour des outils » ouverte dans `hibou-docs` : sans elle, le runner
  garde l’ancien outil de synchronisation du chat.
- Régénérer les jetons et mots de passe utilisés pendant les essais.

## Limites connues

- Non validés faute de matériel : profils au-delà de 4 Go, plusieurs cartes, décodage spéculatif, génération d’images.
- Le modèle 4B se trompe encore souvent comme agent de code (boucles, versions inventées) : préférer 12 Go ou plus.
- pandoc, fourni par Open WebUI, plante sur un processeur sans AVX2 : l’export n’en dépend pas.
- Chaque mise à jour de forge recrée tous ses conteneurs (coupure de quelques secondes).
- Charte : l’accueil du chat vouvoie, le fond du chat et OpenCode web ne sont pas encore aux couleurs Hibou.
